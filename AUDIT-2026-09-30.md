# Rust audit — 2026-09-30

Audited baseline: `6e4d891b8c4f5c8bc4f4042cf57a95db7297c505`, with shared core from Edge
`487babd9f9a47b6e2ac662d1dc6277c01d53747b`. No critical or high severity issue was confirmed.

| Finding | Severity | Change |
| --- | --- | --- |
| WV-01: combined layout ignores total amps and cable power limits | Medium | Colour both totals at 80%/100%, display the strongest applicable alarm, follow the cable rating and keep firmware faults authoritative. |
| WV-02 / WV-05: shared-core data validity and secret creation | Medium | Update the lockfile for the companion fixes; use its matching branch during CI. |
| WV-08: copied installer leaves installed executable behind | Low | Record managed download ownership, recognise older default installs and explicit custom directories, preserve user and in-place source files. |
| WV-09: Windows native HID backend reports successful writes as zero bytes | Medium | Select hidapi's bundled Windows C backend, which returns the completed byte count for synchronous and pending writes. Keep short-write checks. |
| WV-10: unmaintained ttf-parser dependency | Low / maintenance | Replace ab_glyph's font parser with skrifa/read-fonts while retaining ab_glyph_rasterizer for coverage rendering. |

WV-09 was verified in the locked hidapi 2.6.7 source, rather than reproduced on a Windows
Nexus device. The native backend returns `Ok(0)` when `WriteFile` immediately succeeds;
this application's short-write check then rejects an otherwise successful packet.
The selected backend is compiled by the crate's existing build script and remains statically
linked in the release build. Windows source builds now require the normal MSVC C tools.

WV-10 is [RUSTSEC-2026-0192](https://rustsec.org/advisories/RUSTSEC-2026-0192.html), an
unmaintained-library advisory, not a demonstrated vulnerability in this application.
The parser migration removes ttf-parser and owned_ttf_parser from the lockfile; it does
not suppress the advisory. Font selection, per-em sizes and whole-pixel advances remain.

Local verification: 23 Rust tests, mocked installer checks, formatting, Clippy with warnings
denied, preview inspection and cargo-audit passed. The updated 95-package lockfile has no
known vulnerabilities or maintenance warnings on this audit date. Tests cover total/cable
thresholds, firmware faults, font anchors, invalid fonts, frame packets and CLI previews.

Merge the companion [Edge/core audit branch](https://github.com/jlobue10/wireview-xeneon-edge/tree/audit/rust-hardening-2026-09-30)
first. Nexus CI checks out its matching branch while both PRs are open, then falls back to
Edge main. The path dependency means merging Nexus first would leave its lockfile ahead
of the shared core on main.

Hardware validation still needed: real Nexus writes/disconnects, iCUE coexistence, Segoe UI
preview appearance and actual Scheduled Task installation/uninstallation on Windows.
CI compilation and fixture tests do not prove device behaviour.
